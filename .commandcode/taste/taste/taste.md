# Taste
- Expects UI work to be responsive and explicitly optimized for mobile view (e.g., stacking layouts, full-width controls on small screens), not just desktop. Confidence: 0.6
- Prefers dashboard page search + filter controls grouped as one cohesive toolbar unit placed inline in the page header row (title → controls → primary action), rather than as a separate standalone card below. Confidence: 0.5
- Keeps agent assets in Cursor's conventions (skills as `.cursor/skills/<name>/SKILL.md`, rules as `.cursor/rules/*.mdc`) and expects other agents/tools (e.g. CommandCode) to consume those same files rather than duplicating or copying them into a second location — a single source of truth for both tools. Confidence: 0.7
- Values a lean always-loaded context: prefers not to bloat the per-turn memory file (e.g. `AGENTS.md`) with extra imports when the content is already condensed there, accepting that scoped detail stays on-demand instead. Confidence: 0.55
- Wants project-defined skills/rules actually applied in the work, not just registered — expects the agent to load and follow them when relevant. Confidence: 0.6
- Names the skill to use explicitly in the request (e.g. `/domain-modeling`) and explicitly authorizes pulling in additional skills when warranted ("and also use other skills if needed") — skill selection is delegated to the agent rather than prescribed only by the user. Confidence: 0.5
- When a feature is ported/reworked from another codebase, expects the agent to diff the new code against that reference implementation and flag dropped or diverging behavior (regressions) rather than reviewing it in isolation. Confidence: 0.5
- For Stripe/payment work, expects the API usage to be grounded in the official Stripe docs (invokes the `/stripe-docs` skill) rather than relying on memory. Confidence: 0.5
- For React/Next.js work, invokes the `/vercel-react-best-practices` skill and expects its concrete rules to shape the implementation and be cited. Confidence: 0.5
- Consciously limits third-party API usage: asks for an external API to be called at most once per user/session and cached, explicitly to avoid rate limits. Confidence: 0.55
- When the agent fills a form field automatically (e.g. a country dial-code prefix), expects the value to stay user-editable and never overwrite what the user already typed. Confidence: 0.45
- For Google Maps Platform work, invokes the official `/google-maps-platform` agent skill and expects its mandated process to be followed and surfaced — grounded API/library lookup before coding, the compliance review, the usage-attribution ID, and the required cost/key-restriction/ToS disclosure block in the final report. Confidence: 0.5
- Treats server-side secret exposure (credentials leaked from public API routes or embedded in page payloads) as a must-fix, verified priority — even when it's pre-existing and outside the current feature's scope. Confidence: 0.45
- Expects a new feature to become a self-contained "module" in the repo's established sense: a Settings feature toggle (default off) surfaced in the Features tab, with its own feature folder, and gated both in the UI and server-side (a hidden button is not a gate by itself). Confidence: 0.55
- Routinely asks for a follow-up bug audit after new work ships ("check for bugs again", "search for bugs in all the new changes"); the scope varies — sometimes narrowed to the risky paths (payments, emails), sometimes the entire change-set ("all aspects, all related code, functions and features and logic"). Fix authorization may arrive in the same request ("...and then fix if there is anything") or as a separate follow-up after seeing the findings, but either way the expectation is that everything found gets fixed in one decisive pass rather than a prioritized subset (e.g. "fix all of them"). Confidence: 0.65
- Dislikes content that reads as AI-generated ("AI slop"), especially user-facing transactional emails; expects generated copy/templates to drop obvious AI tells (generic "Dear X / thank you for your booking" flattery, marketing filler, automated-email boilerplate footers) and to read like a plain, professional human wrote it. Confidence: 0.55
- Wants action links in emails to include the raw URL printed as a visible fallback beneath the button, so the recipient can still reach the page when the button fails to render or be clicked. Confidence: 0.5
- Cares about keeping the codebase lean: periodically asks for a dead-code cleanup sweep ("clean up any unused / abundant code") to remove orphaned files, unused exports, dead settings fields, and orphaned translation keys — expecting candidates to be verified by zero references before deletion, not removed by eye. Also expects the agent to revisit its own earlier artifacts in later passes ("also check what you left in older test") so tests/helpers made obsolete by a change get updated or removed instead of left stale. Confidence: 0.55
- Expects new UI changes to be visually verified in a real browser (screenshots/snapshots, device emulation for mobile) and any resulting errors fixed before declaring the work done, rather than trusting code alone. Confidence: 0.6
- For non-trivial work, wants the agent to first produce a proper plan and present it for review/approval before making any code changes ("make a proper plan then tell me then we'll make the changes"), rather than implementing immediately. Confidence: 0.7
- When a feature/affordance is added to one form surface, expects it to be applied consistently across all form variants (standard, embed, custom) — recurring "fix all inconsistencies" requests. Confidence: 0.55
- Expects the UI to hold up under the longest localized strings in every supported language (de, ru, ar/RTL): translated text must wrap and the control grow rather than overflow or be clipped, and this is treated as a bug to fix at the shared component level, not per-screen. Confidence: 0.55
- Has a branch etiquette: work lands on `master`, then `development` is brought up to date with it (fast-forward/sync + push); the legacy branch (`Legacy`) must never be touched, and calls this out emphatically as a standing rule, not a one-off. Confidence: 0.6
